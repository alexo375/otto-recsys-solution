## 📝 Описание и постановка задачи

Пользовательские сессии состоят из последовательности действий 3 основных типов:
* просмотр товара - `clicks`;
* добавление в корзину - `carts`;
* покупка - `orders`.

**Задача**: Для каждой усеченной во времени сессии пользователя необходимо сформировать списки из топ-20 рекомендованных товаров отдельно для каждого из трех типов целевых действий, которые произойдут после момента обрезки.

Характеристики датасета:
- **Размер**: ~12 млн сессий и более 220 млн событий.
- **Объем данных**: ~11 ГБ сырых данных.
- **Особенность**: Для событий типа `clicks` существует ровно 1 истинное будущее действие, тогда как для `carts` и `orders` таргет может содержать несколько товаров.

## 🧠 Математический аппарат и ML-архитектура

### 📐 Математическая постановка задачи и целевая метрика

Пусть $S_i$ - последовательность исторических событий $i$-й сессии до временной метки обрезки $t_{cut}$:

$$ S_i = \{(aid_{i,j}, type_{i,j}, ts_{i,j})\}_{j=1}^{K_i} $$

Необходимо для каждого типа действия $T \in \{\text{clicks}, \text{carts}, \text{orders}\}$ предсказать упорядоченное множество кандидатов $\hat{Y}_{i, T} = \{aid_{i,T}^{(1)}, \dots, aid_{i,T}^{(20)}\}$.

Качество работы модели оценивается по взвешенной метрике **Recall@20**:

$$ \text{Score} = 0.10 \cdot R_{\text{clicks}} + 0.30 \cdot R_{\text{carts}} + 0.60 \cdot R_{\text{orders}} $$

где $R_{T}$ выражается как отношение суммарного числа угаданных товаров к максимально возможному числу попаданий (ограниченному 20):

$$ R_{T} = \frac{\sum_{i=1}^N |\hat{Y}_{i, T} \cap Y_{i, T}|}{\sum_{i=1}^N \min(20, |Y_{i, T}|)} $$

- $N$ - число сессий в валидационной/тестовой выборке;
- $Y_{i, T}$ - истинные товары, с которыми пользователь взаимодействовал после $t_{cut}$.

---

### 🏗️ Двухуровневая архитектура

Для обработки миллионного каталога товаров используется двухэтапная схема:

1. **Candidate Generation**: Выделение потенциально релевантных кандидатов с помощью матриц совместной встречаемости и других эвристик на основе недавнего взаимодействия.
2. **Reranking**: Модель градиентного бустинга ранжирует сгенерированных кандидатов на основе комплексного вектора признаков.

## 🔬 Эволюция гипотез и эксперименты

Для честной локальной оценки использовалась схема **OOT валидации** на сэмплированной репрезентативной выборке из 30,000 сессий.

### 1. Baseline
- **Подход**: Товары из текущей сессии в обратном хронологическом порядке + топ глобально популярных товаров + базовая матрица совместного взаимодействия по последним $N$ событиям.
- **Результат**: $\text{Weighted Recall@20} = \mathbf{0.3951}$
  - $R_{\text{clicks}} = 0.4012$
  - $R_{\text{carts}} = 0.3301$
  - $R_{\text{orders}} = 0.4266$

### 2. ML-Ранжирование V1. Просадка метрик и анализ причин
- **Идея**: Обучить единую модель LightGBM Ranker на базовых фичах присутствия товара в сессии.
- **Результат**: $\text{Weighted Recall@20} = \mathbf{0.3269}$ ($\downarrow 0.0682$)
- **Вывод**: Просадка произошла из-за узкой и несбалансированной генерации кандидатов, а также нехватки поведенческих и временных признаков.

### 3. Гипотеза 1: Мультитиповые матрицы совместного взаимодействия. Улучшение генерации кандидатов
- **Идея**: Разделить матрицы совместного взаимодействия по типам событий с учетом временного затухания и весов позиций:
  1. `co_click`: связывает кликнутые товары (переходы клик $\rightarrow$ клик);
  2. `co_cart`: связывает добавления в корзину (carts $\rightarrow$ carts / orders);
  3. `co_buy`: специализированная матрица совместных покупок.
- **Результат (без ML-ранжирования)**: $\text{Weighted Recall@20} = \mathbf{0.4066}$ ($\uparrow +0.0115$ по сравнению с baseline)

### 4. Гипотеза 2: Работа над Feature Engineering
- **Идея**: Сформировать обогащенный вектор признаков для каждой пары $(\text{сессия}, \text{кандидат})$, отражающий абсолютную и относительную свежесть взаимодействия, плотность событий и силу связей из со-визитационных матриц.
- **Результат (с ML-ранжированием)**: $\text{Weighted Recall@20} = \mathbf{0.4306}$ ($\uparrow +0.0240$)

### 5. Гипотеза 3: Разделение и специализация моделей по типам событий
- **Идея**: Паттерны просмотров (`clicks`), добавления в корзину (`carts`) и окончательных покупок (`orders`) могут кардинально отличаться. Обучение трех независимых оптимизированных моделей ранжирования под каждый целевой таргет позволит точнее адаптироваться под разные типы действий.
- **Качество моделей на валидации**:
  - `Clicks Model`: **AUC 0.8189**
  - `Carts Model`: **AUC 0.8878**
  - `Orders Model`: **AUC 0.9265**
- **Результат**: $\text{Weighted Recall@20} = \mathbf{0.4737}$ ($\uparrow +0.0431$)
  - $R_{\text{carts}}$ вырос с $0.3904 \rightarrow \mathbf{0.4476}$
  - $R_{\text{orders}}$ вырос с $0.4734 \rightarrow \mathbf{0.5167}$

### 6. Гипотеза 4: Гибридный пайплайн
- **Наблюдение**: Для целевого действия `clicks` пользователь в абсолютном большинстве случаев кликает на свежие товары из текущей сессии (доминирует прямая позиционная эвристика на основе недавних кликов), тогда как для `carts` и `orders` ключевую роль играет ML-ранжирование по кандидатам матриц совместного взаимодействия.
- **Итоговая архитектура**:
  - `clicks`: Сортировка событий сессии по недавнему взаимодействию + fallback на матрицу совместного взаимодействия;
  - `carts`: ML-ранжирование моделью градиентного бустинга;
  - `orders`: ML-ранжирование моделью градиентного бустинга (независимой с `carts` моделью).
- **Результат**: $\text{Weighted Recall@20} = \mathbf{0.4793} \approx \mathbf{0.480}$ ($\uparrow +0.0056$)

## 🛠️ Итоговый состав признаков

Для этапа ранжирования генерируются следующие 20+ признаков:

### 1. Сигналы кандидатов
- `in_session`: флаг присутствия товара в текущей сессии ($0 / 1$);
- `recency`: абсолютная позиция с конца сессии;
- `from_co_click`: кандидат получен из матрицы кликов ($0 / 1$);
- `from_co_cart`: кандидат получен из матрицы корзин ($0 / 1$);
- `from_co_buy`: кандидат получен из матрицы покупок ($0 / 1$).

### 2. Внутрисессионная динамика
- `session_count`: количество взаимодействий с данным `aid` в сессии;
- `first_pos`, `last_pos`: первая и последняя позиция товара в сессии;
- `is_last`: является ли товар самым последним просмотренным ($0 / 1$);
- `relative_recency`: относительное положение $\frac{\text{recency}}{\text{session\_len}}$;
- `recency_weighted_count`: суммарный вес взаимодействий с временным затуханием:
  $$ \sum_{t \in \text{events}} \frac{1}{1 + \frac{t_{end} - t}{10^5}} $$
- `last_item_type`: тип последнего действия над товаром (`click`=0, `cart`=1, `order`=2).

### 3. Мета-признаки сессии
- `session_len`: общее число событий в сессии;
- `unique_items`: число уникальных товаров в сессии;
- `session_duration`: длительность сессии в миллисекундах ($t_{end} - t_{start}$);
- `avg_time_between`: среднее время между событиями в сессии;
- `session_density`: плотность событий ($\frac{\text{session\_len}}{\text{session\_duration}}$);
- `time_since_last_event`: время, прошедшее с момента последнего взаимодействия с данным товаром.
